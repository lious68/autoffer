当前单选与不定项结构均来源于真实页面；真实不定项标题为“不定项”，并非目录中的“不定项选择”。已验证两项同时 selected 与独立取消。判断题使用同布局的两个选项映射为 single，尚需真实页面验证。未验证的补充材料、缺失或重复选项标号会阻止模型推断。图片/公式由模板提供图像区域，走已启用视觉能力的通用模型；真实视觉页面尚待验收。同容器的编程、问答、简答、填空题仅识别题型与题干，不读取已填答案；有通用模型时生成参考答案，等待手动填写后再切题；缺少通用模型则跳过。封闭 Shadow DOM、iframe 及不同页面布局仍不支持。不会为了验证下一题型而提交当前题型答案。

## 实验性动作模块

`index.ts` 将只读的 `extractor.ts` 与可选动作组合注册。题型标签映射到 classification.format，未知领域保持 unknown，不从牛客域名推断学科。判断保留 true-false，填空/编程分别保留 fill-blank/programming；兼容 kind 的投影不丢弃这些语义。

`actions.ts` 与只读提取分开维护，通过选项 ID 对应当前 DOM。单选页面已实际观察到 `.option-item.selected`，旧题容器保留但隐藏；动作过滤隐藏容器，不将 active/focus 当成选中状态。仅在确认选择与期望一致后点击唯一、可见且可用的「下一题」按钮；无法确认时停止，不假定 click 成功。第 15 题实际显示「提交本题型」，没有提交回退路径。不定项多选也已确认使用相同 selected 类，不能把勾选装饰 SVG 当作题目图片。

代码题实际使用开放 Shadow DOM 中的 `pre.prettyprint`，以 NBSP 表示缩进。通用提取器保留 pre/code 中的换行、空格及文本片段相邻关系，将 NBSP 还原为空格。回归用自编代码，不保存真实试题。

全屏控件见 `content/tools.ts`，自动会话位于 `content/session.ts`，持续到末题，没有 5 题上限；最终模型低置信度调用纯翻页而不选择选项，其他复核/异常/提交入口保持观察，切题后自动继续。不修改平台监测逻辑；插件模型驱动的完整链路仍待实测。

`tests/fixtures/nowcoder-directory.html` 与 `nowcoder-choice.html` 仅保留观察到的结构标记，题目文字和标识均为自编占位；不包含候选人信息、考试凭证或真实题库。测试中的 `data-shadow-fixture` 只用于构造开放 shadow root，不是生产选择器。

`nextSection` 只接受明确的「下一题型 / 进入下一题型」按钮，且调用前要求完整连续题号都已作答。该入口目前只有合成回归证据；实际「提交本题型」后的确认流程未读取，不能自动点击提交来猜测后续界面。

## ACM 编程布局

`acm.ts` 在已匹配的 `.question-preview-container` 内按“输入描述 / 输出描述”独立分区，以及 ACM / 时间空间限制标记识别编程题，不要求普通选择题的 `.header > .type`。读取题干、限制、输入输出描述、多个示例与说明；保留 pre/code/br 与 CSS white-space: pre-wrap 的换行，支持开放 Shadow DOM。过滤编辑器、输入框、按钮、装饰图标与隐藏区域，不读取已填代码。

编程题归类为 programming / text。ACM 正式题现接入 code-editor.ts 与 content/code-runner.ts：确认 Monaco 与当前语言，AstraFlow 生成程序后回填、回读、自测；自测通过后点击单题「保存提交」，以新的判题记录全部通过作为已答依据。不点击「提交本题型」或交卷。其他编程布局仍只提供参考答案。示例折叠或输入输出缺失时给出诊断；带图像的 ACM 布局暂不推断，避免漏读。样例或限制变化会更新题目身份，编辑器变化不会。

通过真实页面的 `.header > .example-tag`（例题）和 `.defaultScore`（不计分）区分示范与正式题。两道例题不调用模型，不进入已答/跳过计数或正式报告；连续模式可通过已适配的下一题按钮略过例题。

证据范围：已在用户授权的 Edge 页面读取实际 DOM，确认同时挂载 3 个题目组件，仅 1 个可见。通过扩展真实 `scan` 消息分别读取例 1、例 2、正式题：每次只返回 1 题、warnings 为空；前两项 isExample=true，正式题 isExample=false，正式题包含题干、输入输出和样例。例 2 的多行矩阵样例完整保留换行。夹具保留已观察结构、使用自编题文；未保存真实试题或考试身份信息。验收仅做只读扫描，未调用模型、填写或提交代码。

新增作答链路的证据：真实页面已观察 Python3 编辑器、自测运行、保存提交、运行历史表的运行 ID / 类型 / 结果 / 用例通过率，以及默认代码导致的 ValueError。Monaco API 解析、Element UI 分离表格、成功结果文本与单题提交链路目前只有离线夹具验证；由于考试已结束，不能把离线测试表述为真实场次作答通过。无法确认 API、表结构或结果时明确失败，不假装完成。
